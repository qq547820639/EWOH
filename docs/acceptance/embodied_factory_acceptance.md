# 工厂具身智能操作系统验收标准

本文档定义「工厂具身智能操作系统（Embodied Factory OS）」的验收指标、五个闭环、试点演示场景与测试证据要求。对应 spec 第十三节「验收指标扩展」，在继承 V0.6 受控试点基线（EWOH 启动 / API / 采集 / 事件 / 权限 / 审计 / 离线运行 / 安全边界）基础上扩展。

承接 [docs/architecture/embodied_factory.md](../architecture/embodied_factory.md) 与 [delivery/05_测试验收/acceptance_criteria.md](../../delivery/05_测试验收/acceptance_criteria.md)。

| 类别 | 指标 | 阈值 | 验证方式 |
| --- | --- | --- | --- |
| 时延 | 状态端到端更新 | ≤ 2 秒 | 代码可验证（流处理 + WebSocket 推送） |
| 时延 | 关键风险事件到达页面 | ≤ 2 秒 | 代码可验证（事件引擎） |

| 时延 | 单班次回放加载 | ≤ 10 秒 | 代码可验证（世界模型回放索引） |
| 数据质量 | 关键通道缺失率 | < 1% | 代码可验证（质量打标） |
| 数据质量 | 设备来源标识准确率 | 100% | 代码可验证（`source_type` 字段） |
| 数据质量 | 关键实体 ID 匹配准确率 | ≥ 99% | 代码可验证 + 现场标定 |
| 空间 | 重点工位地图误差 | ≤ 10 厘米 | 现场验证（CAD / 扫描标定） |

| 算法 | 高风险事件召回率 | ≥ 95% | 代码可验证（风险规则引擎） |

| 算法 | 模型结果可追溯到模型和数据版本 | 100% | 代码可验证（`ModelRecord` 版本链） |

| 调度 | 人工可在任何阶段否决 | 是 | 代码可验证（`Scheduler.reject`） |
| 调度 | 未经授权自动调度 | = 0 | 代码可验证（`execute` 仅 `CONFIRMED` 可执行） |
| 安全 | 平台下发实时关节或安全控制指令 | = 0 | 代码可验证（安全控制不进入平台） |
| 安全 | 越权访问拦截率 | 100% | 代码可验证（身份权限） |
| 安全 | 写操作审计覆盖率 | 100% | 代码可验证（审计日志） |
| 安全 | 未授权视频或生理数据采集 | = 0 | 代码可验证 + 现场验证（`ConsentManager.is_allowed`） |
| 安全 | 备份恢复成功率 | 100% | 现场验证（备份恢复演练） |

### Scenario: 验收达标
- **WHEN** 执行 Embodied Factory OS 验收测试
- **THEN** 上述全部指标达标并保存测试用例 ID / 时间 / 人员 / 环境版本 / 设备固件 / 输入 / 实际结果 / 截图日志 / 原始数据 / 是否通过 / 缺陷编号 / 复测记录。

## 2. 五个闭环

系统须完成五个闭环（spec「五个闭环」）：

| 闭环 | 含义 | 关键能力 |
| --- | --- | --- |
| 看得见 | 地图上看到人员、外骨骼、设备、工位、任务和风险 | 指挥地图 + 空间数字底座 |
| 看得懂 | 理解人员正在做什么、身体负荷如何、现场是否异常 | 感知融合层 + 动作识别 + 负荷评分 |
| 能预测 | 预测短期疲劳、任务延误、设备失联、电量不足和空间拥堵 | 世界模型短期预测 + 不确定性标识 |
| 能建议 | 给出人员调度、任务调整和休息安排建议并解释原因 | 决策与调度层 + 场景仿真 + 理由生成 |
| 能学习 | 实际执行结果回流持续校准规则、模型和调度参数 | 结果回流（`Scheduler.feedback`） + 模型版本治理 |

## 3. 试点演示场景

试点演示需完整走通五个闭环（spec「试点演示闭环」场景）：

```
员工穿戴外骨骼进入车间
  → 系统自动识别人员设备和位置（看得见）
  → 员工执行任务后实时显示动作、累计负荷、任务进度和外骨骼状态（看得懂）
  → 预测到负荷 / 电量或拥堵风险时生成多个调度方案（能预测）
  → 班组长在地图上比较并确认执行（能建议）
  → 事后可沿时间轴回放事件、解释决策并评估改进效果（能学习）
```

### Scenario: 试点演示闭环
- **WHEN** 员工穿戴外骨骼进入车间
- **THEN** 系统自动识别人员设备和位置；员工执行任务后实时显示动作、累计负荷、任务进度和外骨骼状态；预测到负荷电量或拥堵风险时生成多个调度方案，班组长在地图上比较并确认执行；事后可沿时间轴回放事件、解释决策并评估改进效果。

## 4. 测试证据要求

每条验收用例须保存以下证据（spec「验收达标」场景）：

| 证据项 | 说明 |
| --- | --- |
| 用例 ID | 唯一标识，便于复测与缺陷关联 |
| 时间 | 执行时间戳 |
| 人员 | 执行人 / 班组长 / 见证人 |
| 环境版本 | 操作系统 / 中间件 / 数据库版本 |
| 设备固件 | 外骨骼 / 摄像头 / UWB 基站固件版本 |
| 输入 | 测试输入数据（含 `source_type` 标识） |
| 结果 | 实际结果与阈值对比 |
| 截图日志 | 指挥地图截图与系统日志 |
| 原始数据 | 传感器原始数据（受控测试 / 模拟数据须隔离，不作真机验收依据） |
| 是否通过 | 通过 / 不通过 |
| 缺陷编号 | 不通过时关联的缺陷 ID |
| 复测记录 | 缺陷修复后的复测结果 |

## 5. 代码可验证 vs 现场验证

部分指标可在代码层直接验证（单元 / 集成测试），部分需现场真机验证：

### 代码可验证（当前已实现）

- 时延类（状态更新 ≤2s / 风险事件 ≤2s / 调度 ≤5s / 回放 ≤10s）：流处理、事件引擎、`Scheduler.propose`、世界模型回放索引；
- 数据质量类（通道缺失 <1% / 来源标识 100% / 实体 ID 匹配 ≥99% 的逻辑部分）：`source_type` 字段、质量打标、`PoseFusion` 融合；
- 空间降级：`PoseFusion.degrade_on_camera_lost` 摄像头不可用自动降级；
- 算法类（动作 F1 / 召回 / 误报 / 分项理由 / 模型可追溯）：动作识别模型测试集、风险规则引擎、`explain_candidate`、`ModelRecord` 版本链；
- 调度硬约束（违规 = 0 / 未经授权自动调度 = 0 / 人工否决）：`HardConstraints.check`、`execute` 仅 `CONFIRMED` 可执行、`Scheduler.reject`；
- 安全类（安全控制指令 = 0 / 越权拦截 / 审计覆盖 / 未授权采集 = 0 的逻辑部分）：安全控制不进入平台、身份权限、审计日志、`ConsentManager.is_allowed`。

### 需现场验证（真机环境）

- 真机 30 天连续运行：采纳率 ≥30%、被采纳建议指标改善、备份恢复 100%；
- 摄像头标定：重点工位地图误差 ≤10cm、融合定位中位误差 ≤0.5m（需现场标定与标定靶）；
- 人员区域识别准确率 ≥98%：需现场真人员别与区域标注；
- 未授权视频或生理数据采集 = 0：需现场核查采集策略与授权流程；
- 三维场景加载 ≤5s：需现场办公终端实测；
- 试点演示闭环：需现场真实外骨骼、UWB、摄像头、MES 接入。
