# 工厂具身智能操作系统（Embodied Factory OS）九层架构

本文档是「工厂具身智能操作系统」升级的总体架构说明，承接 [delivery/02_技术规范/architecture.md](../../delivery/02_技术规范/architecture.md) 中的九层架构概览，给出每一层的职责、输入/输出、与 V0.6 受控试点基线的关系，以及贯穿全栈的静态/动态分离、多传感器融合、事件驱动世界模型、多目标调度、人在回路、不可变安全边界等核心原则。

本系统是纯 Python stdlib（核心代码零第三方依赖）+ SQLite 兼容数据库的实现基线；流处理层在工程部署中可选 Redis Streams/NATS/PostgreSQL/时序数据库/对象存储，但核心契约与表结构保持 SQLite 兼容，不引入对特定中间件的硬依赖。

## 0. 与 V0.6 基线的总体关系

V0.6 受控试点基线已确立五层架构（设备与现场层 / 边缘接入层 / 本地推理层 / 数据与业务层 / 应用层）与四区部署（设备区 / 边缘区 / 平台区 / 展示区），并冻结了真实设备只读接入、身份权限、审计、四区部署与 P0 验收。

九层架构是五层架构在「具身智能」方向上的**细化与扩展，不是替换**：

| V0.6 五层 | 九层架构（扩展后） | 关系 |
| --- | --- | --- |
| 设备与现场层 | 1. 设备与现场层 | 保留并扩展（新增 UWB/摄像头/环境/MES 接入） |
| 边缘接入层 | 2. 边缘适配层 + 3. 流处理层 | 拆分：适配与消息标准化独立为边缘适配层；实时流与存储独立为流处理层 |
| 本地推理层 | 5. 感知融合层 + 6. 工厂世界模型层 | 扩展：单设备推理升级为多传感器融合 + 事件驱动世界模型 |
| 数据与业务层 | 4. 空间数字底座（新增） | 新增统一空间层级与坐标体系 |
| 数据与业务层 → 应用层之间 | 7. 决策与调度层 + 8. 场景仿真层 | 新增多目标调度与方案仿真 |
| 应用层 | 9. 指挥地图与本地助手 | 收敛：单文件静态页独立为指挥地图前端 |

四区部署结构原样保留，九层均映射到四区之上（见下文第 11 节）。

## 1. 设备与现场层

- **职责**：承载所有现场物理设备与传感器，包括外骨骼控制器（含 IMU、力矩、穿戴生理）、UWB 基站与标签、摄像头、环境传感器（温度/振动/噪声/空气质量）、MES/工单/PLC/AGV 接口。设备本地安全控制（急停、限扭、关节实时控制、助力闭环、限速、失联安全态）保留在设备控制器本地，平台不得绕过。
- **输入**：物理世界的人员动作、设备状态、环境变化、生产工单。
- **输出**：原始遥测帧（外骨骼 IMU/力矩/电量/姿态）、UWB 定位坐标、摄像头视频流或边缘结构化结果、环境读数、MES 工单与设备状态。
- **与 V0.6 关系**：V0.6 已接入外骨骼只读遥测；本层在原契约上扩展接入 UWB、摄像头、环境传感器与 MES，不改变外骨骼安全控制本地化原则。

## 2. 边缘适配层

- **职责**：在原统一适配层契约（身份 / 心跳 / 电量 / 故障 / 遥测 / 缓存补传 / 安全状态 / real/controlled_test/simulated/replayed/stale/offline 来源隔离）基础上，新增摄像头、UWB、MES/工单、环境传感器适配器；负责时间同步、消息标准化、缓存补传；摄像头在边缘侧完成人体检测与骨架提取，中心平台默认不长期保存完整视频。所有原始字段进入平台前必须转换为统一语义模型，厂商私有字段不泄漏到上层业务。
- **输入**：设备与现场层的原始帧与状态。
- **输出**：统一语义消息（entity_id / worker_id / event_time / source_type / pose / load / device / quality），边缘骨架结果，丢包与时钟偏移质量指标。
- **与 V0.6 关系**：V0.6 边缘接入层的身份/心跳/缓存补传/来源隔离契约保留；本层新增多类适配器与统一语义转换。统一语义模型定义见 [docs/data/multimodal_schema.md](../data/multimodal_schema.md)。

## 3. 流处理层

- **职责**：承载实时事件流与多模态存储。实时事件流使用 Redis Streams 或 NATS；业务数据使用 PostgreSQL（SQLite 兼容表结构）；高频遥测使用时序数据库；图片/视频/点云/三维资产使用对象存储；前端推送使用 WebSocket。负责事件防抖、去重、时序对齐、质量打标。本层是九层架构的「数据总线」，所有上层均通过本层订阅/发布。
- **输入**：边缘适配层输出的统一语义消息。
- **输出**：去重对齐后的事件流、按保留策略分层存储的数据、WebSocket 推送帧。
- **与 V0.6 关系**：V0.6 已有事件总线与分层保留策略；本层引入多模态存储分离（时序/对象/关系/流），但核心表结构保持 SQLite 兼容，不引入对特定中间件的硬依赖。

## 4. 空间数字底座

- **职责**：建立集团→工厂→车间→产线→区域→工位→设备/人员/任务的统一空间层级与坐标体系；每个实体具备唯一 ID、父级空间、坐标、朝向、边界框、状态、数据来源、置信度、更新时间、版本；提供统一空间坐标变换 API；静态空间底图（厂房结构/产线/设备外形/工位/通道/禁区/摄像头视锥/UWB 基站覆盖区）与动态实体（人员位置骨架/外骨骼状态/AGV 叉车物料/当前任务/告警/风险热力图/预测轨迹）分离；输出 GeoJSON / GLB / 3D Tiles / 点云 / Gaussian Splat / JSON 拓扑，建模分 L0/L1/L2/L3 四级。
- **输入**：流处理层事件、CAD/BIM/平面图/设备布局等静态资料、UWB/视觉等动态观测。
- **输出**：空间实体记录、坐标变换结果、静态底图与动态实体图层、拓扑邻接关系。
- **与 V0.6 关系**：V0.6 仅有区域（zone）概念；本层是新增的统一空间底座。详细规范见 [docs/spatial/coordinate_system.md](../spatial/coordinate_system.md)。

## 5. 感知融合层

- **职责**：融合 UWB 坐标 + 外骨骼 IMU + 视觉检测骨架 + 设备状态 + 工位占用 + MES 任务 + 环境信息，输出人员统一位置、人体姿态、当前动作、工位占用、人员—设备—任务绑定、数据质量与置信度、异常冲突。融合规则优先可解释，产生传感器冲突事件；摄像头不可用时降级到 UWB 与外骨骼继续推断并降低置信度。

### 多传感器融合公式

人员状态由多源加权融合得到，可解释且可降级：

```
人员状态 = f( UWB位置, 外骨骼IMU姿态, 视觉骨架, 工位语义, 任务上下文 )
```

具体含义：
- **UWB 位置**：提供人员粗粒度绝对坐标（工位级），作为位置主源；
- **外骨骼 IMU 姿态**：提供人体躯干俯仰/侧倾/关节角/步态，作为姿态与动作主源；
- **视觉骨架**：提供人体关键点与姿态校验，作为姿态交叉验证与遮挡场景补充；
- **工位语义**：提供 UWB/视觉坐标到工位语义的映射（签到/占用）；
- **任务上下文**：提供当前任务期望动作与工位，作为先验约束。

融合规则（可解释，非黑箱）：
1. UWB 与视觉同工位 → 高置信；
2. UWB 与视觉不一致 → 产生传感器冲突事件，记录冲突详情与各源置信度，不静默丢弃；
3. 摄像头遮挡但外骨骼 IMU 与工位签到正常 → 继续推断但降低置信度；
4. 任一源缺失 → 降级融合，置信度按缺失源权重下降，不中断输出；
5. 低置信度不向上游生成强建议。

- **输入**：流处理层多源消息、空间数字底座的工位语义与坐标变换。
- **输出**：人员统一状态（位置/姿态/动作/工位占用/绑定关系）、传感器冲突事件、质量与置信度。
- **与 V0.6 关系**：V0.6 本地推理层是单设备动作识别与风险规则；本层升级为多传感器融合，原规则与动作模型作为融合层的一个输入源保留。

## 6. 工厂世界模型层

- **职责**：以事件驱动结构维护当前状态、历史状态、实体关系、事件因果链、短期预测、模型不确定性；支持沿时间轴回放事件、解释决策、评估改进效果。

### 事件驱动世界模型链

事件链覆盖一次完整作业闭环，每一步产生可追溯事件并写入因果图：

```
员工进入区域
  → 与外骨骼绑定
    → 领取任务
      → 到达工位
        → 开始搬运
          → 累计负荷上升
          → 电量下降
          → 工位积压
            → 生成调度建议
              → 班组长确认
                → 任务重分配
                  → 结果回流（校准规则/模型/调度参数）
```

每个事件携带 source_type、设备型号、固件版本、协议版本、规则或模型版本、数据质量、置信度、更新时间，并关联空间实体；事件之间以因果边相连，支持从任一调度决策回溯触发上下文、累计负荷与电量趋势、工位积压、建议生成与确认记录、执行结果回流。

- **输入**：感知融合层输出的人员统一状态与冲突事件、空间实体状态、MES 任务流。
- **输出**：当前世界状态快照、事件因果图、短期预测（疲劳/任务延误/设备失联/电量不足/空间拥堵）及其不确定性、回放索引。
- **与 V0.6 关系**：V0.6 有结构化事件引擎（事件防抖/证据窗/可追溯）；本层在原事件引擎上扩展为事件因果链与世界状态模型，新增传感器冲突事件、调度建议事件、方案确认事件、结果回流事件。

## 7. 决策与调度层

- **职责**：实现多目标优化调度，目标函数如下：

### 多目标调度目标函数

```
J = w1·产量 + w2·准时率 − w3·安全风险 − w4·人体负荷 − w5·移动距离 − w6·换岗成本
```

- 产量、准时率为正向收益项；
- 安全风险、人体负荷、移动距离、换岗成本为负向代价项；
- 权重 w1..w6 可由工厂配置，**每次调整必须记录调整前后值、操作人、时间、原因，权重不得由算法自行隐藏决定**；
- 调度流程：硬约束过滤 → 候选人员生成 → 多目标评分 → 方案模拟 → 理由生成 → 人工确认 → 执行结果回流。

硬约束过滤（违反则不进入候选，评分明细须体现拦截原因）：技能资质、工位授权、健康禁忌、禁区、班次休息规则、外骨骼型号兼容、设备故障、安全规则。

- **输入**：工厂世界模型层的当前状态、短期预测、实体关系；工厂配置的权重与硬约束。
- **输出**：候选方案（含评分明细、硬约束拦截原因、理由）、调度建议事件、结果回流记录。
- **与 V0.6 关系**：V0.6 有任务打分（task-ranker）；本层升级为多目标调度优化器，首期使用约束优化 + 启发式，不用强化学习。

## 8. 场景仿真层

- **职责**：在调度执行前生成至少三个方案，每个方案展示分项指标而非仅总分。方案类型：保持现状 / 最小调整 / 产能优先 / 安全与负荷均衡优先 / 设备异常应急。
- **每个方案展示**：预计产量、延误风险、人员负荷变化、行走距离、外骨骼电量消耗、拥堵变化、受影响人员、关键假设、置信度。
- **输入**：决策与调度层的候选方案与评分、世界模型当前状态与预测。
- **输出**：方案对比视图（分项指标）、关键假设与置信度、受影响人员清单。
- **与 V0.6 关系**：新增层，V0.6 无场景仿真。

## 9. 指挥地图与本地助手

- **职责**：独立于现有静态页面的 `ui/command_map/` 前端。布局：中央地图 + 左侧组织车间产线图层 + 右侧选中实体详情 + 顶部班次产量风险设备概况 + 底部时间轴事件流播放控制 + 右下本地助手入口。至少 9 种地图模式（生产/人员/外骨骼/人体负荷/安全风险/设备/环境/调度/数据质量），任何时候只突出一个主要模式。核心页面：全厂态势地图、车间产线地图、人员与外骨骼详情、工位详情、事件中心、调度方案比较、时间轴回放、数据质量中心、模型与规则管理、本地自然语言助手。

### 本地大模型角色约束
本地大模型仅承担：自然语言查询、事件总结、调度方案解释、规则检索、历史案例检索、交接班摘要、异常根因假设、报告生成。**不直接负责实时控制，不直接取代调度优化器**；调度结果必须来自结构化算法，大模型负责解释；大模型不得虚构传感器数据或调度结果（解释必须引用结构化算法输出的真实结果）。

- **输入**：空间数字底座图层、世界模型状态与事件流、调度与仿真方案、模型与规则版本。
- **输出**：指挥地图渲染、时间轴回放、调度方案比较、自然语言查询与报告。
- **与 V0.6 关系**：V0.6 单文件静态页（static/index.html）保留为最小回退；新能力进入独立前端工程 `ui/command_map/`。

## 10. 贯穿全栈的核心原则

### 10.1 静态/动态分离原则
静态空间底图（厂房结构/产线/设备外形/工位/通道/禁区/摄像头视锥/UWB 基站覆盖区）与动态实体（人员位置骨架/外骨骼状态/AGV 叉车物料/当前任务/告警/风险热力图/预测轨迹）分离。**人员位置高频更新时，静态空间底图不被重新构建，仅动态实体层刷新**，避免每秒重建三维场景。静态底图按版本长期保存；动态实体按分层保留策略（高频遥测 7—30 天 / 分钟聚合 6—12 月 / 事件证据按闭环周期）。

### 10.2 数据来源隔离
所有空间实体、感知融合结果、世界模型状态、调度方案、视觉识别结果必须携带 source_type（real / controlled_test / simulated / replayed / stale / offline）。受控测试或模拟数据与 real 数据物理或逻辑隔离，不作为真机验收依据。

### 10.3 人在回路（强制）
试点和早期生产阶段调度系统只能提出建议，由班组长或授权人员确认后执行；高风险建议必须附带理由；系统不得根据单次算法结果直接处罚员工；员工应能申诉、标记误判或说明特殊情况。调度先影子运行只记录不执行，与班组长方案对比达标后进入建议模式，最后才允许有限自动化且不涉及设备安全控制；**未经授权自动调度为 0**。

### 10.4 不可变安全边界
急停、限扭、关节实时控制、助力闭环、限速、失联安全态必须保留在外骨骼设备控制器本地，平台不得绕过。扩展为：
- 平台下发实时关节或安全控制指令为 0；
- 调度系统不得绕过人工确认直接执行；
- 未经授权自动调度为 0；
- 安全控制不进入平台的原则同样适用于决策与调度层、场景仿真层与本地大模型。

### 10.5 五个闭环
系统须完成五个闭环：看得见（地图上看到人员、外骨骼、设备、工位、任务和风险）、看得懂（理解人员正在做什么、身体负荷如何、现场是否异常）、能预测（预测短期疲劳、任务延误、设备失联、电量不足和空间拥堵）、能建议（给出人员调度、任务调整和休息安排建议并解释原因）、能学习（实际执行结果回流持续校准规则、模型和调度参数）。

## 10.6 不可违反的架构硬约束（护栏）

为保证「离线运行 / 零依赖 / 安全边界」三项产品级卖点在长期演进中不被侵蚀，以下为架构硬约束，任何 PR 不得违反：

1. **零第三方运行时依赖（V0.6–V0.7）**：核心代码仅使用 Python 标准库；`pyproject.toml` 的 `project.dependencies` 必须为 `[]`。开发/CI 依赖仅可出现在 `[project.optional-dependencies].dev`（ruff/bandit/pytest），不得进入运行时。
2. **流处理层必须可插拔**：实时事件流、业务数据、高频遥测、对象存储统一经 `edge/bus.py` 定义的接口契约访问；当前为进程内参考实现（`threading.Lock` + `deque` 环形缓冲）。生产部署可在**同一接口**下替换为 Redis Streams / NATS / PostgreSQL / 时序数据库 / 对象存储，上层调用方不得直接 `import` 具体中间件 SDK。前端实时推送当前为 1s HTTP 轮询（见验收指标总表），V0.8 引入 SSE，规模化再切换 WebSocket。
3. **安全控制不进入平台**：任何代码不得写入急停、限扭、关节实时控制、助力闭环、限速、失联安全态等设备安全闭环参数；调度 `execute` 仅在 `CONFIRMED` 后标记 `EXECUTED`，无自动执行旁路。
4. **来源隔离不可绕过**：所有实体/事件/推理结果必须携带 `source_type`（real / controlled_test / simulated / replayed / stale / offline），受控与模拟数据不作为真机验收依据。

护栏守护：CI（`test.yml`）增加步骤断言 `dependencies == []`；安全边界由 `server.py` / `scheduler/orchestrator.py` 的代码不变量与单元测试保证（见 `docs/operations/security_boundary_audit.md`）。

## 11. 四区部署映射

九层架构沿用 V0.6 已冻结的四区部署，本扩展不改变四区边界与安全控制策略：

| 四区 | 承载的九层 |
| --- | --- |
| 设备区 | 1. 设备与现场层（含设备本地安全控制） |
| 边缘区 | 2. 边缘适配层 + 边缘视觉推理 + 3. 流处理层边缘侧 |
| 平台区 | 3. 流处理层中心侧 + 4. 空间数字底座 + 5. 感知融合层 + 6. 工厂世界模型层 + 7. 决策与调度层 + 8. 场景仿真层 |
| 展示区 | 9. 指挥地图与本地助手 |

四区之间的网络分区、身份权限、审计与离线运行策略原样保留。
