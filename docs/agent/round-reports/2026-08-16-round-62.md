## Completed

1. **ADR-041（决策 1-4）**：标准库最小 SMTP 客户端；渠道启用 =
   配置完整性 fail-closed；共享助手三渠道；配置面 + 客户端标签。
2. **`email-transport.ts`**：RFC 5321 子集（EHLO / AUTH LOGIN /
   MAIL FROM / RCPT TO / DATA+dot-stuffing / QUIT；多行回复解析；
   10s 超时；无新依赖）。传输形态 v1 显式边界：无凭据=明文（内网
   中继）；带凭据必须 `EWOH_SMTP_SECURE=1` 隐式 TLS——非 TLS+凭据 →
   `smtp_auth_requires_tls` 绝不明文传凭据（fail-closed）；STARTTLS
   升级显式记录为后续演进。SMTP 5xx → `smtp_rejected_<code>` 显式。
3. **派发器多渠道**：`PUSH_CHANNELS=['lark','email']`；按启用集
   `inArray` 动态领取（渠道未配置 = 显式禁用不建 doomed 行）；逐行
   按 channel 分派（lark webhook / email SMTP），单行失败独立，CAS
   写回 sent/failed 不变。
4. **三渠道通知**：`insertAndonNotifications`（oee + ingest 共用，
   §31）在 app/lark 之外增加 email 行（配置时建）——开灯与 SLA
   升级三渠道同语义。
5. **配置面**：env 7 键（EWOH_SMTP_HOST/PORT/SECURE/USER/PASS/
   FROM/TO）deploy/.env.example 文档化 + env-inventory 双向校验
   （117→124 documented PASS）；通知中心渠道标签 += 邮件、推送
   状态面标题泛化（多渠道路径）。
6. **测试**：email-transport.spec 10 例（配置解析 fail-closed /
   消息体渲染 / SMTP 协议序 / AUTH LOGIN base64 / 非 TLS 凭据显式
   拒绝 / 5xx 拒绝 / dot-stuffing）；dispatcher +3 例（email 投递 /
   未配置禁用 / 混合渠道独立失败）；oee +1 例（SMTP 三渠道）；
   client 标签；default jest 248 suites / **1821** tests、client
   jest 114 suites / 944 tests 全绿；双 tsc PASS。
7. **§36 评估**：andon-loop 升 Implemented（矩阵 **48/7/0/1**）。
