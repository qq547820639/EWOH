# Round 24 Report — 2026-08-16

## 当前目标（Current Objective）
NO-03a（Phase 3 世界模型契约层）：在 Factory Truth 原则下建立跨运行时统一的"工厂实体模型契约"——
一个 45 类的实体类别登记表（entityKindRegistry）+ 实体声明字段契约 + 权威投影（authoritative
projection）分工约定，由 JSON Schema 锁定、Python/TypeScript 双运行时同构实现、独立 JS 仲裁器审计、
Golden Scenario 双执行器验证。不允许任何一方成为"事实的第二个来源"。

## 本轮完成（Completed）
1. **ADR-015**（`docs/decisions/ADR-015-factory-entity-model.md`）：定义 Factory Entity Model 的三层结构
   （Identity 层 / World-State 层 / 领域层），确立 45 类实体类别登记表为唯一权威清单（Kind 为
   `kind:value` 键的 kind 部分，与 ADR-006 Identity 的 42 类、ADR-008 World State 快照的 22 类保持
   子集一致性：22 ⊆ 45 由审计门强制），并规定 Entity Declaration 与 Entity Snapshot 的权威投影分工，
   避免"实体信息"与"世界状态"双源漂移。

   EntityKind 常量 45 值 + EntityDeclaration 字段契约）+ `contracts/entity/test-vectors.json`（11 条，
   覆盖 normal / unknown_kind / bad_entity_id / snapshot-subset 等正反例）。
3. **双运行时同构实现**：Python `src/edge_platform/contracts/entity_model.py`（stdlib-only）与
   TypeScript `ewoh-spark-app/shared/entity-model.ts`，字段名、枚举值、错误码逐字对齐；
   `shared/entity-model.spec.ts` 新增 5 例。
4. **审计门扩展**：`scripts/audit-domain-contracts.js` 新增 entity 域（仲裁 + 11 向量 + 校验 +
   entityKindRegistry 登记检查 + `entity_snapshot_subset` 交叉校验——用世界模型快照的 22 类逐一检查
   必须在实体模型 45 类中），本轮全量 **277/277 PASS**。
