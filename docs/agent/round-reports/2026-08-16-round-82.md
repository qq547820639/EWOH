   dispatch` 确定性幂等（double-dispatch CAS）；subject=plan:\<id\>；
   requiresApproval=false；selected.reason=dispatched:\<count\>

   链接；auditTrail actor=user:\<id\>|system:dispatch；validateDecision
   门；`maxDecisionRisk` 聚合规则锁测试。
3. **dispatch-coordinator 重构**：事务末将 kind #4（预占）+ kind #5
   （派工）记录**单次**读-追加-回写 decision_records_json
   （projectReservationDecisionRecords + appendDecisionRecords；
   投影缺口/追加失败 log 显式绝不阻断派工主流程 §2）；getPlan 读回
   自动携带。
4. **测试**：decision-projection.spec +3 例（判定事实 / 风险聚合
   max 规则 / 缺省 actor + 幂等 + 缺口显式）+ dispatch-integration
   .spec 主链路断言补强（kind #5 台账 + validateDecision 门 +
   getPlan 读回携带）；default jest 264 suites 1950→**1953** tests
   全绿；双 tsc PASS。
5. **§36 评估**：canonical-decision-model 证据深化（保持 Implemented
   ——kind #5 生产调用链）；派工链全链留痕（kind #2 审批 → kind #4
