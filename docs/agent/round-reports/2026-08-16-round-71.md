## Completed

1. **ADR-050（决策 1-3）**：推进腿落点 = recordActuals（反馈唯一写
   路径）；推进边界显式声明；taskActionPath 纯函数（与边缘
   shortest_task_path 同语义）。§29 十八问全部作答。
2. **assignment 推进**：actualStart → dispatched CAS→executing；
   actualEnd → {dispatched,executing} CAS→completed（无 start 观测时
   单事件 dispatched→completed，不伪造中间状态）；每次推进写
   ewohAssignmentEvent（fromStatus/toStatus/actor/reason）。
3. **task 推进**：`taskActionPath`（TASK_ACTIONS 锁步图 BFS 最短合法
   链）逐动作 `transitionTaskState`（每步 CAS + 审计）——dispatched→
   receive→start→executing（start）、executing/received/paused→
   complete 链（end）；边界显式：exception 不隐式 resolve
   （dispatcher 显式动作）、pending_dispatch 不收 start（乱序）、
   终态 no-op、skip+log（§33 不吞异常）。
4. **幂等**：CAS + 已一致 no-op（重复回填覆盖式更新 + 推进零副作用）。
5. **可观测**：recordActuals 返回推进 summary（advancedAssignments/
   advancedTaskSteps/skips），recordTaskActuals 响应 additive 透出；
   既有 stub 返回 undefined 兜底零值（向后兼容）。
6. **测试**：execution-feedback-advancement.spec 6 例（start/end 链
   推进 + 事件审计 / 无 start 单事件 / 幂等 / 乱序与 exception 边界 /
   无执行事实不推进）；task-state-machine-contract.spec 7→8 例
   （+taskActionPath 路径/不可达/空路径/链自洽）；scheduler-facade-
   characterization 响应契约更新（additive 透出）。
7. **§36 评估**：canonical-execution-model 全绿升 **Implemented**
   （矩阵 50/5/0/1→**51/4/0/1**）。
