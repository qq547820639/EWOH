# Round 67 — NO-12w：邮件 STARTTLS 升级（ADR-046）

日期：2026-08-16（EWOH 长周期 Agent）

## Current Objective

NO-12w：email-transport 渠道演进——SMTP 客户端支持机会式 STARTTLS
（RFC 3207 子集），使 587 端口凭据投递可用；凭据安全不变式延续
（AUTH 仅 TLS 后，绝不明文传凭据）；ADR-041 v1 明文/隐式 TLS 传输
形态边界消除（§20/§33）。

## Completed

1. **ADR-046（决策 1-3）**：机会式 STARTTLS 会话流（凭据 + 明文 →
   STARTTLS → 升级 → 重新 EHLO → AUTH）；服务器不支持（502）→
   `smtp_auth_requires_tls`（与 v1 错误码兼容，客户端重试语义不变）；
   升级失败 → `smtp_starttls_failed:<reason>` 显式（§33 不吞异常）。
2. **SmtpConnection 接口扩展**：`startTls()` + `tlsActive` 可变属性
   （测试缝不变：注入 fake 即可驱动协议序）。
3. **sendEmail 会话升级**：EHLO →（凭据 + 明文时）STARTTLS（期望 220）
   → `startTls()` → 重新 EHLO → AUTH LOGIN；无凭据明文不发起
   STARTTLS（内网中继路径不变）；`EWOH_SMTP_SECURE=1` 隐式 TLS
   语义保留（skip STARTTLS + TLS 后 AUTH 分支不变）。
4. **realSmtpConnector socket 升级管理**：`removeAllListeners('data')`
   → `tls.connect({socket, servername})` → secureConnect 等待（10s
   超时 → `smtp_starttls_failed` 显式）→ 重新 attach 数据监听。
5. **测试**：email-transport.spec 10→12 例（+STARTTLS 升级序
   EHLO→STARTTLS→EHLO→AUTH / 服务器 502 拒绝 → smtp_auth_requires_tls /
   无凭据明文不发起 STARTTLS）；channel-dispatcher.service.spec
   email fakes 适配回归；default jest 250 suites / **1856** tests
   （+2）、client 114/944 全绿；双 tsc PASS。
6. **§36 评估**：andon-loop 证据深化（邮件渠道传输形态 v2；矩阵计数
   不变 49/6/0/1）。
