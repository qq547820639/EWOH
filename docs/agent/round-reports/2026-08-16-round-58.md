# Round 58 — NO-12n：Andon 通知推送渠道（ADR-037，飞书 webhook）

日期：2026-08-16（EWOH 长周期 Agent）

## Current Objective

NO-12n：andon-loop 推送腿——安灯开灯/SLA 升级只有 in-app 通知
（channel=app），现场人员离开应用即失联。为 ewoh_notification（自
ADR-030 起已备 channel/sentAt/errorMessage 列）接通第一真实推送渠道
（飞书自定义机器人 webhook），并修复既有通知缺 orgId 的 §15 缺陷。

## Completed

1. **ADR-037（决策 1-5）**：飞书 webhook 为第一真实渠道（无 SDK/无
   新依赖）；投递状态落权威通知行（pending→sent/failed，CAS）；开灯
   与 SLA 升级双触发点入通知；通知中心推送状态面；无契约/事件/迁移。
2. **`channel-dispatcher.service`**：封闭注册表 `PUSH_CHANNELS=['lark']`
   （只注册有真实投递实现的渠道——邮件 SMTP 未实现不入表，§33）；
   `buildLarkMessage` 纯函数（安灯事实渲染）；`realLarkTransport`
   fetch POST + 5s 超时 + 非 2xx 显式抛错；15s tick 领取 pending lark
   行 → CAS 写回 sent（sentAt）/failed（errorMessage）；CAS 未命中
   不重复投递（§20）；单行失败独立；in-process 防重叠；未配置
   webhook = 渠道显式禁用（log + 不建 doomed 行）。
3. **人工重试**：`NotificationService.retryPush`（仅 failed 推送行
   → pending；app 通知/非 failed 显式拒绝）+ 控制器
   `POST /api/notifications/:id/retry`（dispatcher/workshop_lead/
   global_admin）；`toNotification` 增补 sentAt/errorMessage（additive）。
4. **双触发点接线**：oee `openAndon` 与 SLA 升级统一
   `createAndonNotifications`（app 恒建 + lark 配置时建；externalRef
   指向 Andon 事件主事实）；**§15 修复通知缺 orgId（孤儿行消除）**。
5. **客户端**：审批控制台通知中心「推送状态（飞书）」分组（渠道
   标签 + 待投递/已投递/投递失败（errorMessage）+ 重试按钮）；
   `notificationChannelLabel`/`notificationState` 纯逻辑（未知渠道
   原样透出）。
6. **配置与面**：`EWOH_LARK_WEBHOOK_URL` + `EWOH_NOTIFICATION_
   DISPATCH_INTERVAL_MS`（env-inventory 117/118 PASS）；
   OpenAPI +1 路由 392 零漂移（spec 581）。
7. **§36 评估**：andon-loop 推送腿闭环（真实调用链：开灯 → 通知行 →
   webhook 投递 → sent/failed 显式 → 人工重试）；缺口收窄为邮件
   渠道 + 边缘 AndonRaised 上行（矩阵计数不变 46/9/0/1）。
