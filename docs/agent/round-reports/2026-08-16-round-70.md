     _sync_task_status_on_dispatch + set_assignment_status↔update_task

2. **TS 状态机数据化（决策 1）**：nextTaskStatus 改由 `TASK_ACTIONS`
   （action→from→to 数据表）+ `TASK_NON_TERMINAL`/`TASK_TERMINAL`
   驱动——契约消费面，行为与既有 switch 逐字一致（task.service.spec
   回归绿）。
3. **锁步 spec**：`task-state-machine-contract.spec.ts` 7 例——
   task.yaml 逐条比对（无缺失/无契约外转换）+ 11 状态 × 14 动作穷举
   负例（期望值由契约推导）+ 检查器负测试（人为缺失转换必须检出，
   与 Python 负测试同纪律）+ task-lifecycle 分类集合锁步（历史别名
   pending/queued/done 显式声明）。
4. **差异边界声明（决策 2）**：task 状态机=任务事实唯一状态机；
   AssignmentStatus=派工协调词汇表（dispatched→dispatch、cancelled→
   cancel 显式映射；计划拒绝不隐式取消任务）；execution 词汇表=
   执行观察（联动 NO-13a 立项）。
5. **决策 3**：执行反馈完成腿 NO-13a 立项（§30 先修契约/边界）。
6. **文档复核**：walkthrough R-3 行更正（遗留已收口 + 剩余缺口精确化）。
