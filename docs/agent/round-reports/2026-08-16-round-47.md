## Completed

1. **ADR-027（决策 1-4）**：同一 severity 列两套相反词表（边缘 L1=最严重
   vs 云 UI L3=最严重）→ 唯一词表 critical>high>medium>low；无风险判定
   显式 `unknown`（§33 绝不伪装 normal）；按生产者意图逐类确定性迁移
   （非机械映射）；入口归一化 `normalizeEventSeverity`；客户端全量收敛。
2. **入口归一化**（shared/risk.ts）：`normalizeEventSeverity`（规范直通 /
   L1→critical / L2→high / L3→medium / 其余显式 unknown）+
   `EVENT_SEVERITY_UNKNOWN`；与 `normalizeSeverity` fail-closed 分工
   （域契约校验拒绝 vs 事件事实落账显式标记）。
3. **12 个服务写入点迁移**：ERP L1/L2→critical/high；信息性生命周期事件
   （learning/proposal/agent/orchestrator/knowledge/simulator/inference/
   simulation）L3→low；DeadLetter→medium；ingest 边缘事件→显式 unknown
   （ADR-027 注释）；world 时间线标记→low。
4. **5 类消费方收敛**：priority-engine（{critical,high,medium}=risky，
   注释词表更新）、supervisor（critical/high + 文案）、learning
   riskOutcomeRate（canonical + 过渡期 legacy UNION 注释）、gamification
   （critical 风暴）、dashboard（口径注释修正）。
5. **客户端全量收敛**：EventCenterPanel 筛选/徽章、Timeline 与
   TimelinePanel 配色（critical=红/high=橙/medium=黄/low=绿/unknown=灰）、
   AlertToast `aggregateL3`→`aggregateCriticalEvents` 更名（L3=最严重的
   旧词表语义即新词表 critical）、DeviceConfigDrawer、perf fixture、
   replay/entityDetailData 测试夹具。
6. **测试夹具收敛**：priority-engine / world-state-derive / scheduler-
   domain / world / timeline / oee / agent / gamification 相关 spec 与
   client 测试全部切换规范词表（维护/质量 spec 的 legacy 输入保留——
   它们是入口归一化语义测试，非词表残留）。
7. **§36 评估**：canonical-risk-model 全链路接线收口（矩阵 42/13/0/1
   计数不变——条目此前已 Implemented，本轮证据深化）；project-state
   partial 移除 canonical-risk-model。
