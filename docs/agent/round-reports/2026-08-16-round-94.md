## Completed

1. **仓库事实发现六类跨租户缺口**：
   - conflict 读面无 org 条件且 **ewoh_scheduling_conflict 无 RLS
     policy**（025 八条 policy 不含 conflict）——跨租户冲突生命周期
     泄漏（应用层唯一执行面，无 DB 兜底）；
   - feedback list()/deriveKpis() 读全租户反馈行；kpi.aggregate 无
     orgId 时全局聚合——跨租户执行事实聚合（与 R-91 同类泄漏）；
   - GET /executions → executionService.list(query) 忽略已有
     opts.orgId 参数（API 面未接线）；
   - GET /plans/:planId/compare/:otherPlanId controller 不传
     userContext——双方案经无守卫 getPlan 读取；
   - policy listVersions() 读全租户策略版本行（应用层无 org 条件）；
   - GET /policy/activations 以 **query 参数 orgId** 过滤——任意
     租户可传任意 orgId 读取他租户激活台账（org 参数欺骗）。
2. **ADR-073**（§29 十八问全作答）：六面闭合 + org 来源修复；无
   DB/契约/OpenAPI 变更。
3. **conflict 读面 org 作用域**：listConflicts(params, actor?)/
   getConflictDetail(id, actor?) → loadAllRows/findRowByConflictId
   org 条件（org 匹配或 NULL 存量；无 actor 保持原查询形状）；
   推导态冲突由本租户快照产生（org 局部）。
4. **feedback/kpi 聚合 org 作用域**：list(orgId?)/deriveKpis(orgId?)
   org 条件；kpi.aggregate 将 orgId 传入 deriveKpis + 冲突计数按
   本租户 actor；comparePolicyVersion 对比 KPI 本租户派生。
5. **execution 读面接线**：execution.service.list 兑现 opts.orgId
   org 条件；queryService/facade/controller 三级 userContext
   透传。
6. **compare 守卫接线**：comparePlansV2 双方案读取经 ADR-071
   getPlan 守卫（跨租户 404）。
7. **policy 读面**：listVersions(orgId?) org 条件 + controller
   userContext。
8. **activation org 来源修复**：controller 以 ctx.primaryOrgId
   取代 query 参数 orgId（org 事实只允许来自认证上下文，§3/§15）。
9. **metrics controller**：GET /feedback 与 /feedback/rows 注入
   userContext（跨租户反馈行 dump 关闭）。
10. **测试**：scheduler-read-org-isolation.spec 7 例（conflict 3
    + feedback 1 + execution 1 + policy 1 + activation 1）；
    facade oracle executionList orgId 合并更新；conflict-lifecycle
    兼容（findRowByConflictId 无 actor 保持原形状）。
11. **门禁全绿**：default jest 267→**268 suites / 2016 tests**、
    client jest 120 suites/970 tests、双 tsc PASS、
    audit-domain-contracts 581/581、openapi 398/590 零漂移、
    repo-facts 39/39、reconcile 6/6 computed=74、feature-status
    32/32、env-inventory 124/125。
12. **§36 评估**：cross-tenant-isolation 证据深化（保持
