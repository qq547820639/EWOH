## Completed

1. **ADR-011 Quality State 入调度（docs/decisions/）**：
   - 活跃质量发现 = status ∈ {open, under_review}（dispositioned/closed 是处置
     终态，处置即解除，无第二套状态源）；
   - **严重度门控**：critical/high → 关联资源硬封锁（*_quality_blocked，
     human-in-the-loop）；medium/low 仅事实可见（工厂常态缺陷，全量封锁会整线
     停滞——工业现实约束）；
   - **关联范围**：links 中 kind ∈ {station, device, person} 才产生资源封锁；
     order/material/batch 是检验对象非调度资源（留 NO-05e MES/工单闭环）；
   - **与维护封锁的语义差异显式声明**：质量事实不改变资源状态（质量不改变
     资源物理可用性，只改变派工决策），维护条件才收敛状态（AD-LC-005）；
   - 否决方案记录：全量封锁 / 全 kind 封锁 / 质量改资源状态。
2. **共享契约视图**（`shared/quality.ts`）：`QualityFindingProjection` +
   `ACTIVE_QUALITY_STATUSES` + `QUALITY_BLOCK_SEVERITIES` +
   `QUALITY_RESOURCE_LINK_KINDS` + `qualityFindingsBlockDispatch()`
   （归一化严重度门控，未知严重度 fail-closed 按封锁 + 留痕回调）。
   `shared/scheduler.ts`：ResourceState + WorldStateSnapshot persons/devices/
   stations 增可选 `qualityFindings`。
3. **投影接线**（`resource-projection.service.ts`）：
   `loadActiveQualityFindings()`（活跃过滤 + 形状守卫 + 资源 kind 限定，同一
   代码路径兼容链式 fake）+ `attachQualityFindings()`（仅事实附着，不改状态）；
   `project()` 与 `projectForSnapshot()` 双路径接线。
4. **资格封锁**（`eligibility.service.ts` + `candidate-engine.service.ts`）：
   `person_quality_blocked` / `device_quality_blocked` /
   `station_quality_blocked`（stationQualityBlockedById 由 candidate-engine
   以共享谓词构建），medium/low 不封锁；legacy L1-L3 归一化触发；未知严重度
   按封锁留痕（fail-closed，不把未知当安全）。
5. **测试**：`quality-projection.spec.ts` **12 例全绿**（附着不升级状态 /

   L1 归一化 / 未知严重度 / station 封锁 / 未封锁不误伤）。
