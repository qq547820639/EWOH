## 9. 事务、幂等、并发与回滚

关键写入必须形成一致的事务边界：业务状态、资源预约、审批、审计和待发送事件。复用或引入事务 outbox/inbox、数据库唯一约束、乐观版本或适当锁机制；不得先成功返回再补写关键证据。

幂等按租户、操作和请求内容定义。同一幂等键相同内容返回稳定结果，不同内容明确冲突。重复事件、重复批准、重复派工、重复回执都必须有并发测试，不能只测串行第二次调用。

验证事务与连接池中的组织上下文不会串用；后台任务、消息消费者和边缘同步也必须显式携带经验证的租户上下文。事务失败时不得遗留不可见预约、孤儿任务、已发送但无记录的命令或错租户缓存。

区分撤销尚未执行的任务、释放预约、回滚软件状态和补偿已发生的实体动作。已加工、已搬运、已消耗等不可逆事实不得被数据库回滚抹掉；输出不可逆范围、补偿任务、残余影响和需要现场处理的项目。

对于 ACK 丢失、部分成功和执行状态未知，设计状态查询、对账与人工接管路径。没有设备侧幂等或可查询结果时，不能承诺物理动作“恰好一次”，也不能盲重试高风险命令。

## 10. 必须打通的核心业务闭环

优先基于现有设备故障辅助重排闭环，贯通主产品 UI、NestJS API、真实本地数据库、边缘服务、模拟设备和运行记忆。只有审计证明确有更合适主线时才调整，并记录理由。

1. 注入带来源、时间和唯一标识的设备故障或人员异常。
2. 校验质量、时钟、缺失、冲突与新鲜度，形成可信、待核实或拒绝使用的明确结果。
3. 基于世界状态计算受影响订单、任务、人员、设备、工位、物料、空间与预约。
4. 在存在可行方案时生成至少两种有实质差异的候选，并提供保持现状/人工接管的比较基线；不可行为唯一事实时解释冲突约束，不伪造可行方案。
5. 展示原因、证据、版本、影响、硬约束、软目标、风险、不确定性和预期指标。
6. 使用独立身份完成审批或拒绝，验证职责分离；符合明确策略的低风险分支可走策略授权。
7. 原子生成任务与预约，通过可靠投递到现场人员、移动端、外骨骼提醒或模拟执行机构。
8. 接收开始、进度、完成、失败及部分完成回执，核实执行者和授权范围。
9. 比较计划与实际的时间、产出、资源、负荷和安全偏差，缺失事实保持未知。
10. 形成可追溯复盘、经验和改进行动，记录证据缺口及适用条件。
11. 经验可产生规则/策略改进提案，经回放、影子比较、审批和版本治理进入后续使用；不得未经验证自动修改生产策略。

主闭环同时提供拒绝、过期、数据恶化、重复消息、权限不足、部分执行、失败恢复、取消和补偿分支。只跑成功路径不算交付。

## 11. 边缘、传感器、外骨骼与数字孪生

建设或修复可替换的传感器、检测设备、设备/执行机构、外骨骼适配接口与模拟器，复用已有连接器和 TCK。模拟器走与真实适配器相同的契约和鉴权路径，不能通过直接改数据库制造闭环成功。

模拟器至少表达设备状态、能力、位置/工位、心跳、电量或健康、任务执行及故障；外骨骼还表达穿戴绑定、会话、姿态/负荷观测、提醒、确认和离线状态。使用固定 seed、可控时钟、明确场景版本及输入。

边缘离线缓存、上行补传、下行收件箱和执行回执必须有持久化语义。验证断网、进程崩溃、重启、ACK 丢失、乱序、重复、延迟、时钟漂移、队列积压和存储不足时的行为。内存 retry 队列不等于可恢复。

重连后校验授权是否过期、设备是否更换、命令是否已执行、事实是否冲突。禁止因网络恢复自动执行已失效的危险命令。对背压、隔离、死信、人工处置和恢复提供用户可见状态。

边缘断网时继续允许的动作必须来自本地有效策略和授权范围。失去可信数据或授权后按风险降级，安全硬约束默认拒绝通过。时间判断区分 wall clock、单调时间和来源时钟，不把客户端时间当作唯一权威。

## 12. 用户工作流与 AI 体验

围绕班组长、调度员、生产主管和现场人员提供完整角色工作流。进入系统就能回答：当前发生了什么、影响谁、我需要做什么、为什么、完成后会怎样。

班次工作台应串联异常与待办、受影响对象、方案卡片及比较、仿真、审批/拒绝、部分派工、撤销/补偿、执行进度、偏差和复盘。优先改进已有页面和上下文联动，不以新增菜单数量衡量完成度。

每条智能建议显示来源、更新时间、新鲜度、适用范围、风险、约束、可信依据和模拟/真实标签。加载、空数据、缺失、过期、冲突、失败和无权限不能都渲染成空白或“正常”。前端乐观状态不能把待确认操作显示为真实完成。

移动端与外骨骼交互适配现场使用：少步骤、大触达区、明确接单与执行确认、可见离线/待同步状态、冲突解决和失败恢复。验证桌面与移动布局、键盘操作、可读性、焦点及必要无障碍规则。

AI 解释使用受租户和权限约束的上下文，回答必须可回到源数据和方案版本。区分事实、推测、建议和未知。模型不可直接访问设备控制接口、绕过审批或调用未授权工具；来自文档、遥测和用户上传内容的指令当作数据处理。

记录模型/提示词版本、检索证据、工具调用、输出和回退原因，并遵循人员数据最小化。无模型服务时提供明确标识的确定性解释/规则回退，不能把模板文本冒充大模型推理。模型建议须经 schema、权限与硬约束校验。

## 13. 多租户、安全、缓存与数据治理

统一检查服务端查询、嵌套关联、聚合统计、导出、搜索、后台任务、消息队列、SSE/订阅、对象存储、签名下载链接、前端 query key、缓存、离线存储和持久化状态的组织隔离。

组织/工厂范围从可信身份上下文派生，不信任客户端传入 org_id。校验对象归属、可访问组织集合、角色和字段权限；列表受限而详情/导出不受限仍算越权。缓存键包含影响结果的租户、身份或权限版本及业务参数。

切换组织、切换账号、权限变更和退出登录时，取消旧请求/订阅，清理或隔离缓存、离线任务和敏感状态。迟到响应不能覆盖当前组织数据。

用至少两个隔离组织和多个角色验证读、写、缓存、推送、后台消费及执行授权。RLS 测试必须包含真实应用运行角色，不能只用超级用户或表 owner 测试。连接池复用、异常回滚、事务重试和并发请求必须覆盖。

核对实际 RLS、迁移、应用过滤与文档声明。全局共享数据须有明确理由及可证明的访问边界；不得用“按设计共享”掩盖租户业务数据泄漏。

审计记录包含身份、租户、动作、对象、关键变化、时间、因果链和授权依据，保护其追加与保留规则。检查密钥、依赖、上传、注入、SSRF、错误泄漏和日志脱敏。安全扫描失败或漏洞数据库不可访问必须显式记录，不能等同“无漏洞”。

人员姿态、负荷、生理与位置等敏感数据按最小必要收集与展示。仿真不能证明临床有效性、人体安全性或设备认证；相关真实结论必须保留明确的现场验证边界。

## 14. 实测比较、参数优化与性能

对本次涉及的重要算法至少实际比较两个适用候选。调度优先核对现有 heuristic/rule-based、CP-SAT、MILP 实现与适配情况，使用相同输入、硬约束、seed、时间限制和目标函数进行公平比较。

覆盖正常负载、资源紧张、无可行解、锁定任务、断线资源、人员资质冲突、物料不足和大规模实例。记录可行率、硬约束违规、目标值、延误、计算时间、超时回退及结果稳定性。使用独立约束校验器检查输出，不让求解器自己证明自己正确。

记录实际执行的求解器与版本。CP-SAT 依赖不可用后回退到启发式，不算完成 CP-SAT 比较；求解器对某规模跳过时单列，不把缺失样本或回退结果当成原算法结果。

参数调优必须有基线、训练/调优与保留验证场景、搜索范围、结果和回退版本。不能只调到固定演示 seed 好看，不能为通过测试放宽硬约束。实际测量失败就修复、换方案或如实降级。

复用现有性能门禁，先审查阈值与测量方法，再实测。性能结果注明硬件、并发、数据规模、冷/热启动、采样次数、p50/p95/p99、错误率和资源消耗。不能只列平均值，也不能把静态推算当成测量。

没有已有适用阈值时，在优化前制定与第一阶段负载匹配的可量化目标，并说明依据；不得看到失败结果后悄悄降低目标。仿真和性能实验持续为技术决策提供证据，而非仅产生报告。

建立测试文件到框架、发现规则、执行命令和 collected/passed/failed/skipped 的映射，检查非标准命名 Python 文件、tools 测试、客户端测试、独立侧车、Playwright 类型配置和单独 .mjs 场景是否遗漏。迁移门禁“没有新增 baseline 失败”不等于迁移全部通过；最终核对实际失败清单与所有应用/验证步骤。

## 16. 必须覆盖的故障与验收矩阵

至少运行并保留以下软件可验证场景，按能力补充边界值：

1. 正常感知到复盘学习的完整闭环；至少两个组织、四类业务角色。
2. 缺失、迟到、过期、冲突、低可信度数据；真实/受控测试/模拟来源隔离。
3. 重复/乱序事件、重复审批/派工/回执、相同幂等键不同内容、并发资源争抢。
4. 越权读写、对象归属伪造、组织切换缓存污染、SSE 串租户与后台上下文错误。
5. 方案审批后世界状态改变、授权过期/撤销、审批人与发起人身份边界、能力停用。
6. 部分派工、执行失败、超时、ACK 丢失、状态未知、取消、补偿和不可逆结果。
7. 边缘断网补传、进程崩溃重启、回执恢复、重连后的过期命令处理和存储压力。
8. 全新数据库安装、旧版本升级、迁移失败恢复、适用的 down/补偿方案和备份恢复演练。
9. 模型服务超时/不可用、无来源解释、工具越权或提示注入，以及规则回退。
10. 求解不可行、求解超时、候选硬约束独立校验、算法公平比较和参数回放。
11. 真实浏览器连接真实本地后端/数据库完成主流程，并覆盖关键失败界面与移动端流程。
12. 从干净隔离环境依据文档启动、运行种子场景、验证证据、停止并再次恢复。

单元测试验证关键规则；集成测试验证真实组件边界；契约测试验证跨语言一致性；仿真测试验证时序与故障；浏览器测试验证用户完成工作。已有 mock 浏览器测试只能证明对应 UI 行为，不能代替真实 API 端到端证据。

浏览器运行时缺失时优先安装或使用可用浏览器工具；仍不可用则完成 API/契约/仿真验证并保留浏览器验收未完成状态。未运行项不得以“理论可跑”补齐。

## 17. 阶段门禁与递归修复

按证据推进阶段，不按文档数量推进：

- G0：恢复上下文、保护现有改动、建立完整清单、隔离环境和可执行验证基线。
- G1：全仓结构理解、能力/缺口/重复/淘汰矩阵、主流程定义与关键技术调研完成。
- G2：世界模型、身份、事件、能力、状态机、授权、事务和边缘边界一致并通过相应测试。
- G3：主产品贯通完整闭环和现场交互，来源、未知、风险和审批状态可见。
- G4：故障、租户、迁移、安全、算法、性能和真实浏览器验收完成。
- G5：当前内容对应的逐行审阅账本达标，独立审查问题修复，完整门禁重新确认，运行文档可复现。

每个完整修改单元执行“检查 diff—针对性验证—自查—必要的独立审查—修复—复验”。集成阶段运行要求的完整检查，不在每个微小编辑后机械重跑全部耗时测试；后续变化按依赖失效相关证据。

每个缺陷记录复现、根因、影响、改动、验证和复测。同类失败重复出现时，重新审视理解、契约或架构，不循环叠补丁。审查者可以挑战方案；你应基于证据重排策略，不能擅自降低用户目标。

全仓审计发现的可修复问题属于本任务范围，不以“历史问题”跳过。优先修复安全、租户、数据一致性和主流程阻塞，再消除已知的其他功能与工程缺陷。不得把本阶段已经确认且本地可修的问题移入“下一阶段”以宣告完成。

不追求“证明永远没有未知 bug”这种不可验证承诺；要求所有已发现、可复现且可在授权范围解决的问题被修复，所有承诺能力有证据，所有剩余不确定性被准确记录。

- 运行文档、演示步骤、角色账号获取方式、排障、恢复和真实硬件接入路径。
- 验证证据索引、递归修复记录、独立审查结论、剩余外部验证清单和恢复入口。

每份运行证据记录命令、工作目录、开始结束时间、退出码、环境/工具版本、数据 seed、输入规模、结果摘要和原始日志路径；绑定 Git HEAD 及未提交工作树内容摘要，不能仅绑定 HEAD 后继续声称所有新改动已验证。敏感值脱敏。

完成要求是：第一阶段承诺的产品能力全部落实；主业务闭环在隔离的真实软件运行链路中通过；必需软件门禁和测试全部 PASS；租户、授权、幂等、回滚/补偿和降级有证据；当前自有代码审阅范围无遗漏；独立审查无未解决的本地可修问题；别人能按文档复现。说明原因不能把 FAIL、SKIP、BLOCKED 或 NOT_RUN 变成验收通过。

若存在必须依赖真实硬件、工厂网络、真实历史数据、授权第三方或现场人的验证，先完成全部可数字化工作，精确列出缺失条件、影响的主张、当前替代验证、剩余现场步骤和验证判据。替代验证不把原验收项自动改成通过。

明确区分“第一阶段软件闭环完成”“现场试点就绪”“真实产线验证完成”和“可生产部署”。如果仍缺任何当前目标要求的工作，不得把 goal 标记完成。真实数据库语义、必需浏览器验收等软件门禁即使受外部条件阻塞，也必须保留未完成状态，相应 G4/G5 不得通过；可提交限定范围的阻塞交接，按实际工具规则记录状态。只有从一开始就明确位于软件完成范围之外的真实现场验证可以列为后续，不得在失败后临时移出范围。

只有当前审阅账本、主流程、质量门禁和独立复核均达到对应范围要求，才能对“代码已经做好了迎接这个愿景的准备”给出有范围、有证据的结论。没有证据时必须回答尚未达到，并指出具体缺口，不能用这句话作惯例收尾。

## 19. 最终报告

全部可执行工作完成并经过自我复查后，提交一个自包含的报告，包含：

1. 愿景与目标复核：逐项标记已实现、已验证、受限、未满足及证据，说明软件与现场结论的边界。
2. 已完成产品能力：围绕用户工作流说明，不用页面数或文件数替代价值。
3. 全仓理解范围：文件/行覆盖分母、哈希绑定、分类排除项、独立审查范围及结论。
4. 修改文件和模块：关键职责变化、删除/替换内容及迁移兼容性。
5. 架构决策：候选方案六维对比、真实来源、选择理由和实际落地位置。
6. 实际运行方式：准确命令、目录、依赖、端口、账号配置、启动/停止/复位和主闭环演示步骤。
7. 全部验证命令及结果：PASS/FAIL/SKIP/BLOCKED、环境、时间、规模和日志链接，不能只写“测试全部通过”。
8. 递归修复记录：重要缺陷、根因、修复、复测与独立审查反馈。
9. 算法和参数实验：比较方法、测量结果、选择与局限。
10. 未验证外部条件：具体依赖、替代验证、未覆盖语义及现场验收要求。
11. 剩余风险：影响、触发条件、缓解、证据与后续判据。
12. 下一阶段可自动执行的建设方向：依赖、入口和完成标准，不能夹带本次应完成却遗漏的事项。

如环境允许，保持最终本地产品可访问，并提供健康检查结果与停止方式。没有完成的内容如实说明，不把脚本存在、测试替身成功、历史记录或未来计划写成已实现成果。
