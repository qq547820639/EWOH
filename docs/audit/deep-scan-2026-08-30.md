## 二、发现清单（按严重度排序）

### F-1｜E2E 环境未启用事务强制开关，E2E 保真度缺口
- **定位**：`ewoh-spark-app/test/e2e/standalone-e2e-server.ts`（环境装配处）；对照 `server/database/request-database-context.ts:41-48`
- **类型**：测试环境配置 / 架构一致性
- **严重度**：**中**
- **影响**：E2E 全链路走了「根句柄回落」路径（每请求打印 NEST-504 警告），而生产按 `EWOH_DB_REQUIRE_TX=1` fail-closed 强制 GUC/RLS——**E2E 验证的不是生产数据库访问路径**，RLS 语义回归可能漏测
- **触发条件**：任何未显式设置 `EWOH_DB_REQUIRE_TX=1` 的部署/测试环境
- **修复方向**：`standalone-e2e-server.ts` 默认 `process.env.EWOH_DB_REQUIRE_TX ??= '1'`；若暴露现有 E2E 的非事务查询，逐一修复（这正是该开关的价值）
- **佐证**：2026-08-29 真实后端 E2E 日志出现 `[RequestDatabaseContext] NEST-504: …回落根句柄（无 GUC/RLS）`

### F-2｜gamification 委托链防御风格不一致（潜在 NPE 模式）
- **定位**：`server/modules/gamification/gamification.service.ts:603`（`await this.schedulerService!.dispatchPlanV2(...)`）
- **类型**：潜在空引用 / 防御一致性
- **严重度**：**低**（当前不可达：574 行 `if (existing.status === 'approved' && this.schedulerService)` 是唯一入口）
- **影响**：同文件 574、938 行用守卫，603 行用裸非空断言——未来复制此模式到无守卫路径即产生真实 `TypeError: Cannot read properties of undefined`
- **触发条件**：当前无触发路径；风险在未来演进
- **修复方向**：函数首行改早退守卫（`if (!this.schedulerService) throw new BadRequestException('scheduler 未装配')`），与 938 行风格统一

### F-3｜work-orchestration 锁管理在 HTTP 读路径做同步文件 I/O
- **定位**：`server/modules/work-orchestration/work-orchestration.service.ts:381-389`（`getResources()` 内每资源 `loadLockFile()`）+ `:1517`（`releaseExpiredLock` 内同步 `deleteLockFile`）；`artifactsDir()`（`:1527-1540`）每次调用重跑 `existsSync` 目录探测
- **类型**：性能 / 事件循环阻塞
- **严重度**：**低-中**（当前资源量小；随锁文件数线性放大）
- **影响**：列表接口（GET）在 Node 事件循环上执行 N 次同步磁盘读 + 潜在同步删文件；多并发请求时相互阻塞
- **触发条件**：锁文件数量增长 或 并发请求叠加
- **修复方向**：① `loadLockFile` 改 `fs.promises`（方法链已有 async 上下文）；② `artifactsDir()` 结果模块级 memoize；③ 锁过期清理移出读路径（惰性 → 启动时/定时清理）

### F-4｜邮件传输自实现 SMTP 的外围风险面
- **定位**：`server/modules/notification/email-transport.ts:163-176`（手写 SMTP 会话循环写命令）
- **类型**：健壮性审查待完成（未逐行审读）
- **严重度**：**待定**（列为本报告 L3 未覆盖项的代表性高危点）
- **影响**：自写 SMTP 常见缺陷：TLS 升级（STARTTLS）缺失/未校验、多收件人失败隔离、响应码多行读取、超时后 socket 泄漏
- **触发条件**：真实邮件通道启用时
- **修复方向**：深读该文件并对照 RFC 5321 检查清单；或评估替换 nodemailer（依赖已可引入）

### F-5｜`travel-cost.service.ts` 比较器内非空断言（模式性风险）
- **定位**：`server/modules/scheduler/travel-cost.service.ts:65-66,476-479,498-499`（`from!.x`/`to!.y`）；`plan-compare.service.ts:80-82`（`x!.personId`）
- **类型**：潜在空引用（模式性）
- **严重度**：**低**（排序比较器内元素由调用方保证存在）
- **影响**：上游数据契约变化（如快照中实体被删除）时，`!` 把 undefined 变成静默 NaN 传播而非显式报错
- **触发条件**：候选池含悬空实体引用
- **修复方向**：入口处集中校验缺失实体并显式拒绝（`assertTravelEndpoints(from, to)`），比较器内移除断言

### F-6｜Python 测试套件 socket 资源告警
- **定位**：`src/edge_platform/tests/`（unittest 输出 6 处 `ResourceWarning: unclosed <socket.socket>`）；`scripts/replay_device.py:104`（脚本级 socket 无 finally）
- **类型**：资源泄漏（测试态 + 脚本态）
- **严重度**：**低**（生产运行时连接层 `ark_vision.py` 的 `_PinnedHTTP(S)Connection.connect` 为标准 http.client 模式，资源随连接对象关闭，无泄漏）
- **影响**：测试日志噪音掩盖真实告警；脚本工具长跑句柄堆积
- **触发条件**：每次全量 unittest；replay_device 长时间使用
- **修复方向**：测试 teardown 显式 `close()`；replay_device 加 `try/finally`

### F-7｜正面确认（排查过、确认无问题的模式）
