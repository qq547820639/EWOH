# EWOH 生产 SLO 与错误预算（SLO & Error Budget）

> 定义核心 API 的服务等级目标（SLO）、错误预算计算、容量基线、告警降噪规则。
> 本文档为生产工程深化（Phase 5）的文档交付物，数值为**建议基线**，需在真实试点
> 压测与生产运行后校准（归入外部验证项）。不依赖部署环境。

## 1. 适用范围

- **对象**：EWOH 平台核心 API（NestJS 平台区，`/api/*` 业务端点），以及边缘平台
  （`src/edge_platform`）关键采集/推理链路。
- **排除**：静态资源、`/health`、`/api/security/policy` 等基础设施探针不计入错误率
  （但计入可用性）。

## 2. SLO 定义

| 指标 | SLO 目标 | 说明 |
|---|---|---|
| **可用性** | 99.9%（月度） | 月度容许不可用 ≤ 43.8 分钟 |
| **延迟 P95** | ≤ 800 ms | 与 `perf-budget.mjs` 的 `api-p95` 预算一致 |
| **延迟 P99** | ≤ 2000 ms | 长尾容忍上限 |
| **慢查询** | ≤ 1000 ms | 与 `perf-budget.mjs` 的 `slow-query` 预算一致 |
| **错误率** | ≤ 0.5%（30 天窗口） | 仅计 5xx/无响应；4xx 客户端错误不计入 |

### 2.1 可用性分级

| 级别 | 可用性 | 月度预算 | 场景 |
|---|---|---|---|
| 核心 API | 99.9% | 43.8 分钟 | 平台读写、调度、状态 |
| 边缘采集 | 99.5% | 3.6 小时 | 断网可缓冲回放，容忍度更高 |
| 报告/导出 | 99.0% | 7.3 小时 | 非实时，可异步 |

## 3. 错误预算计算

错误预算 = 总时间 × (1 − SLO)。

| SLO | 月度预算 | 滚动 30 天测算 |
|---|---|---|
| 99.9% | 43.8 分钟 | 可用性 = 1 − (不可用分钟 / 43200) |
| 99.5% | 3.6 小时 | 同上 |
| 99.0% | 7.3 小时 | 同上 |

- **消耗规则**：任何 5xx、超时、无响应发布（除 4xx 客户端错误外）均消耗预算。
- **红线**：当错误预算耗尽（可用性跌破 SLO），**冻结新功能发布**，进入修复期
  （专注可靠性，不扩围业务）。
- **恢复**：预算恢复正常（回到 SLO 之上）后解除冻结。

## 4. 容量基线

| 维度 | 基线 | 说明 |
|---|---|---|
| 并发连接 | 200 并发（试点） | 依据平台区 NestJS 默认处理能力，需压测校准 |
| 每秒请求 | 峰值 500 RPS | 压测目标，需真实环境验证 |
| 延迟目标 | P95 ≤ 800ms / P99 ≤ 2000ms | 见 §2 |
| 数据库 | PostgreSQL 17，连接池 20（`DB_POOL_MAX`） | 见 `.env.standalone.example` |
| 慢查询阈值 | 1000ms（`EWOH_DB_SLOW_THRESHOLD_MS`） | 记录到审计/监控 |
| 语句超时 | 30s（`EWOH_DB_STATEMENT_TIMEOUT_MS`） | 防止长查询拖垮池 |

> 真实容量基线需在具备 PG/容器的环境压测（`k6`/`ab` 等），本机无法实测，归入外部验证。

## 5. 告警降噪规则

为避免告警风暴，按以下规则配置告警：

1. **分级触发**：仅当错误率超过告警阈值的持续窗口才告警（如错误率 > 2% 持续 5 分钟；
   而非单次 5xx 即告警）。
2. **可用性聚合**：按滚动 30 天窗口聚合可用性，跌破 99.5% 触发 P1；跌破 99.9% 触发 P2。
3. **延迟降噪**：P99 告警使用 5 分钟分位数，避免单次抖动触发；P95 异常持续 10 分钟才告警。
4. **4xx 排除**：4xx 客户端错误（参数错、权限不足、未认证）不计入错误率告警。
5. **依赖告警降级**：外部依赖（Redis/S3/对象存储）故障产生聚合告警，不逐请求刷屏。
6. **静默窗口**：灰度发布窗口内（发布后 10 分钟）允许瞬时错误率上升，不触发 P1。
7. **去重合并**：同一根因（如某 DB 连接池耗尽）合并为单条告警，附影响面。

### 5.1 告警阈值速查

| 告警 | 阈值 | 级别 |
|---|---|---|
| 可用性跌破 99.5% | 滚动窗口 | P1 |
| 可用性跌破 99.9% | 滚动窗口 | P2 |
| 错误率 > 2% 持续 5 分钟 | 5xx | P2 |
| P99 > 2000ms 持续 10 分钟 | 延迟 | P2 |
| 慢查询 > 1000ms 占比升高 | 数据库 | P3 |
