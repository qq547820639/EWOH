## 0. 访谈前准备清单

### 环境准备（D-2，与工程协同）

- [ ] **测试账号**：至少 3 种角色（dispatcher / safety_admin / workshop_lead）各一个
- [ ] **仿真数据**：确保测试环境有 ≥3 条待审批方案（shadow/proposed 状态）+ ≥5 条告警（open/acknowledged/processing 各有）
- [ ] **方案详情可访问**：`/o/scheduling_plan/:id` 路由已实现（J1 已交付）
- [ ] **告警详情可访问**：`/o/alert/:id` 路由已实现（J2 已交付）
- [ ] **浏览器**：Chrome 最新版，全屏模式（避免地址栏泄露内部 URL）
- [ ] **录屏工具**：OBS 或系统自带（macOS: QuickTime / Windows: Xbox Game Bar）
- [ ] **录音设备**：手机录音笔（备用），主用电脑录音
- [ ] **纸笔**：观察记录表打印 5 份（本文 §5）

### 招募邮件模板

```
主题：EWOH 系统使用体验访谈邀请（45-60 分钟）

您好，[姓名/工号]，

我是 [产品负责人姓名]，负责 EWOH 系统的产品规划。我们正在做一轮系统改进，
希望听听实际使用者的体验和建议。

访谈内容：
- 了解您日常使用 EWOH 的场景和习惯
- 请您完成一个简单操作任务（边操作边说明思路）
- 听取您对系统改进的建议

时长：约 45-60 分钟
时间：[提供 2-3 个时段选择]
地点：[会议室 / 线上链接]
报酬：[如有]

参与完全自愿，访谈内容仅用于产品改进，不会涉及绩效评估。
录音仅用于后续整理笔记，报告中会脱敏处理。

如果方便，请回复确认可参加的时段。非常感谢！
```

### 知情同意话术（访谈开始前，逐字朗读）

> "感谢您抽出时间。在开始之前，我需要先说明几点：
> 
> 第一，这次访谈的目的是了解您使用 EWOH 系统的真实体验，帮助我们改进产品，
> 不会对您的绩效产生任何影响。
> 
> 第二，我会录音和录屏，仅用于事后整理笔记。报告中不会出现您的姓名，
> 只会使用角色代称（比如'调度员 A'）。
> 
> 第三，访谈中如果任何问题让您不舒服，可以随时跳过或中止，完全没有问题。
> 
> 第四，访谈时长约 45-60 分钟，中间可以随时休息。
> 
> 请问您是否同意继续？如果同意，我开始录屏和录音。"

（等待明确的口头同意 + 点头/手势确认后开始录制）

## 1. 完整访谈脚本

### A. 开场与暖场（5 分钟）

**过渡语**：
> "好，录音已开始。我们先聊聊日常工作，不着急。"

| # | 问题 | 追问话术 | 探测目标 |
|---|------|---------|---------|
| A1 | "您在这个岗位多久了？主要负责哪些事？" | "一天的工作大概是什么节奏？" | 资历 + 职责范围 |
| A2 | "一天里您大概会打开 EWOH 几次？通常在什么场景下打开？" | "是主动打开还是收到提醒后打开？" | 使用频率 + 触发模式 |
| A3 | "如果只能保留 EWOH 的三个页面，您会留哪三个？为什么？" | "这三个页面之间有没有什么联系？" | **核心：真实高频路径 + IA 心智模型** |

**记录要点**：A3 的回答直接影响 IA 设计——如果受访者选的三个页面与导航分组完全吻合，说明分组合理；如果选了跨组的页面，说明用户心智模型与设计不符。

---

### B. 任务走查：跨页面任务（20 分钟，核心）

**环境**：测试账号已登录，有 ≥1 条待审批方案。

**任务引入**（逐字朗读）：
> "接下来我想请您完成一个任务。不需要快，按照您平时的习惯来操作就好。
> 
> 任务是这样的：**系统刚生成了一个一个新的排产方案，请您审批它，**
> **然后确认现场是否开始执行。**
> 
> 操作过程中请您边做边说出您的想法——比如'我现在要去哪里找这个方案'、
> '我要点这个是因为……'，想到什么说什么。可以开始了吗？"

**主持人行为**：
- ❌ **不提示**（"你试试侧边栏？"）
- ❌ **不纠正**（"其实这里应该点……"）
- ✅ **只追问**（"您刚才为什么去那个页面？"）
- ✅ **记录操作路径**（页面切换次数、方式、犹豫点）

**走查中观察记录表**（实时填写）：

| 操作步骤 | 页面/位置 | 行为描述 | 犹豫/回退？ | 耗时估计 |
|---------|---------|---------|-----------|---------|
| 1 | | | 是/否 | |
| 2 | | | 是/否 | |
| ... | | | 是/否 | |

**走查后追问**（必须问，按顺序）：

| 追问 | 话术 | 探测 |
|------|------|------|
| B-Q1 | "刚才您为什么切到 [具体页面]？在找什么？" | 理解切换动机（信息需求 vs 操作需求） |
| B-Q2 | "有没有哪一步您觉得'应该能直接点过去，但找不到入口'？" | **H1 核心证据**：跨页断裂点 |
| B-Q3 | "如果这一步能少切一次页面，对您影响大吗？" | 痛点强度量化 |
| B-Q4 | "您平时审批方案的时候也是这个流程吗？有没有更快的方式？" | 现有变通方式（workaround） |

---

### C. 审批场景（10 分钟，验证 H2）

**过渡语**：
> "我们聊聊审批。您在审批台应该见过不少待批条目。"

| # | 问题 | 追问话术 | 验证假设 |
|---|------|---------|---------|
| C1 | "您在审批台看到一条待批时，第一眼能判断出它是什么吗？" | "具体是怎么判断的？看哪个字段？" | **H2**：是否依赖实体名称 |
| C2 | "有没有出现过'不知道在批什么，得先去别处查'的情况？能讲一次具体经历吗？" | "那次最后怎么解决的？花了多久？" | H2 强度 + workaround |
| C3 | "如果审批条目上直接显示对象名称和关键指标（比如任务名称、方案的核心指标），对您的决策帮助有多大？" | "哪些信息最重要？排个序？" | OD-1 价值量化 |

> ⚠️ 主持人注意：审批台实际承载 `task` / `dangerous_action` / `control_request` 三类
> （不是调度方案）。提问时让受访者就自己**真实见过的条目**回答，不要引导。

---

### D. 终态与跟进（10 分钟，验证 H3）

**过渡语**：
> "审批完了之后的事情。"

| # | 问题 | 追问话术 | 验证假设 |
|---|------|---------|---------|
| D1 | "您派工/审批完成之后，通常怎么确认事情落实了？" | "是主动去查还是等别人通知？" | 当前闭环机制 |
| D2 | "有没有'做完了但不知道结果如何'的情况？当时您怎么处理的？" | "花了多长时间才确认？" | **H3**：终态黑洞 |
| D3 | "您希望系统在完成后主动告诉您什么？" | "用什么方式通知比较好？（弹窗/消息/邮件/首页卡片）" | 终态行动条的 UX 方向 |

---

### E. 风险与告警（10 分钟，为 J2 探路）

**过渡语**：
> "最后一个话题，聊聊告警和风险处置。"

| # | 问题 | 追问话术 | 验证假设 |
|---|------|---------|---------|
| E1 | "收到告警后您通常做什么？会点进去看详情吗？" | "如果没点，是为什么？" | **H4**：告警处置入口 |
| E2 | "判断一条告警严不严重，您需要哪些信息？现在能拿到吗？" | "如果拿不到，您怎么判断？" | 告警详情的信息架构需求 |
| E3 | "处置一条告警平均要花多久？卡在哪个环节最久？" | "那个环节为什么卡？" | 告警处置效率瓶颈 |

---

### F. 收尾（5 分钟）

| # | 问题 | 目的 |
|---|------|------|
| F1 | "如果 EWOH 只能改进一件事，您希望是什么？" | **强制排序**：暴露最高优先级痛点 |
| F2 | "有什么是您现在不得不做、但觉得完全没必要做的？" | 浪费型工作识别 |
| F3 | "还有什么我没问到、但您觉得重要的？" | 兜底：捕获意外发现 |

**结束语**：
> "非常感谢您的时间，今天的访谈对我们的改进方向帮助很大。
> 后续如果有需要确认的地方，我可以再联系您吗？"

## 2. 访谈后 24h 行动

- [ ] 完成录屏转文字（可用飞书/腾讯会议的自动转写，人工校对关键段落）
- [ ] 将观察记录表填入结构化观察表（见研究方案 §6）
- [ ] 每条观察标注：对应假设（H1/H2/H3/H4/新发现）、痛点强度、频率、workaround
- [ ] 标记需要后续确认的模糊表述

## 3. 常见坑与应对

| 场景 | 应对 |
|------|------|
| 受访者紧张、说话少 | "没有标准答案，我就是想听您的真实感受" |
| 受访者说"都挺好的" | "那有没有哪件事如果改了，会让您更方便？" |
| 受访者开始抱怨其他系统 | 记录但不深挖，拉回 EWOH 话题 |
| 受访者问"这个功能什么时候上线" | "感谢反馈，我先记录下来，后面评估优先级"——不做承诺 |
| 走查任务卡住 >3 分钟 | "没关系，这个步骤确实不太容易找到。您觉得理想情况下应该怎么操作？" |
| 受访者提到敏感生产数据 | 不记录具体内容，只记录"涉及 [X 类型数据]" |
| 时间超出 60 分钟 | 在 D 部分后询问"我们还有大约 10 分钟，您希望继续聊告警话题，还是先结束？" |
