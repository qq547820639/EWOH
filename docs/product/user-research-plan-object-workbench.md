# EWOH 用户研究方案 — 对象工作台与风险处置

> 版本：v1.0 ｜ 日期：2026-09-01 ｜ 状态：**待执行（阻塞 J1 价值验证与 J2 开工）**
> 定位：这是**研究方案（Research Plan）**，不是研究结果。
> ⚠️ 本文**不含任何用户访谈数据或结论**——EWOH 目前没有任何真实用户研究记录，
> 所有"用户痛点"均来自代码静态证据推导，本方案的目的正是**补齐这块空白**。
> 关联：`docs/product/PRD-object-workbench.md`（J1，Q-5）、`docs/product/PRD-risk-journey.md`（J2，Gate G-2）

---

## 1. 为什么必须做

J1（对象工作台）已交付并通过全部工程验证，但存在一个根本缺口：

| 项 | 状态 |
|----|------|
| 工程实现 | ✅ 完成（P0 六项 + P1 三项） |
| 自动化测试 | ✅ 前端 142 套件/1257 用例、后端 290 套件/2253 用例全绿 |
| **用户价值验证** | ❌ **零**——无访谈、无埋点基线、无可用性测试 |

**后果**：我们无法回答"用户真的更快了吗"。这不是工程问题，是产品判断缺依据。
J2 风险旅程已把"J1 价值验证"设为强阻塞 Gate（G-2），本方案是该 Gate 的执行路径。

---

## 2. 研究目标（要验证的假设）

本研究不追求"挖掘新需求"，而是**证伪或确认三条已由代码推导出的核心假设**：

| # | 假设 | 来源 | 若不成立的影响 |
|---|------|------|--------------|
| **H1** | 用户在**页面之间**切换时确实感到断裂与迷路，且这是主要效率损耗来源 | 代码证据：23/25 页面零出链 | 对象工作台的价值主张不成立，需重新定位 |
| **H2** | 审批人在审批台**看不出对象是什么**，会因此犹豫或切换到其他页面确认 | 代码证据：审批台渲染 `entityType + entityId` | OD-1 优先级需下调 |
| **H3** | 派工/处置完成后的"不知道下一步去哪"是真实痛点 | 代码证据：终态仅剩静态文本 | 终态行动条价值有限 |
| H4（探索性） | 告警处置链路存在类似的上下文缺失 | 代码证据：告警无详情路由 | 影响 J2 的范围与优先级 |

## 3. 方法

**主方法：半结构化访谈（1 对 1，45–60 分钟）**
辅以**任务走查（Task Walkthrough）**——让受访者在真实环境完成指定任务，观察而非询问。

选择理由：
- 样本量小（3–5 人）但深度足够，适合 B 端专业角色；
- 任务走查能暴露"用户说不出但实际存在"的问题（回忆偏差）；
- 成本可控，2 周内可完成。

**不采用**问卷（样本基数太小，无统计意义）、不采用 A/B 测试（尚无足够流量）。

---

## 4. 受访者

覆盖 `lib/navigation.ts` 定义的 6 种角色中的 3 种高频角色：

| 优先级 | 角色 | 人数 | 招募理由 |
|--------|------|------|---------|
| P0 | 调度员（dispatcher） | 2 | J1 主用户，覆盖排产→审批→派工全链路 |
| P0 | 安全员（safety_admin） | 2 | J1 审批 + J2 告警处置双覆盖，安全关键 |
| P1 | 班组长（workshop_lead） | 1–2 | 兼具审批与现场处置视角 |
| — | 设备员 / 一线操作员 | 可选 | 若时间允许，补充移动端视角 |

**招募标准**：每周使用系统 ≥3 次、在岗 ≥3 个月；避免只选"配合度高"的用户。

## 5. 访谈提纲

### A. 开场与角色画像（5 分钟）

1. 你在这个岗位多久了？主要负责哪些事？
2. 一天里你会打开 EWOH 多少次？通常在什么场景下打开？
3. 如果只能保留 EWOH 的三个页面，你会留哪三个？为什么？
   > 探测：了解真实高频路径，验证 IA 分组是否符合心智模型。

### B. 任务走查：跨页面任务（20 分钟，核心）

给受访者一个真实任务，请他**边操作边说明**：

> 「系统刚生成了一个新的排产方案，请你审批它，并确认现场是否开始执行。」

观察并记录：
- 一共切换了几次页面？用了什么方式（侧边栏 / ⌘K / 书签）？
- 在哪个步骤出现犹豫、回退、或"我得去别处看一下"？
- 是否出现反复刷新、打开多个标签页对照？
- 完成后，他知道去哪里看执行结果吗？

**关键追问**（走查后）：
- 刚才你为什么切到那个页面？在找什么？
- 有没有哪一步你觉得"应该能直接点过去，但找不到入口"？
- 如果这一步能少切一次页面，对你影响大吗？

### C. 审批场景（10 分钟，验证 H2）

4. 你在审批台看到一条待批时，第一眼能判断出它是什么吗？
5. 有没有出现过"不知道在批什么，得先去别处查"的情况？讲一次具体经历。
6. 如果审批条目上直接显示对象名称和关键指标，对你的决策帮助有多大？

> ⚠️ 注意：当前审批台实际承载的是 `task` / `dangerous_action` / `control_request` 三类，
> **不是**调度方案（J1 PRD C-6）。提问时应让受访者就自己真实见过的条目回答，
> 不要引导他说"调度方案"。

### D. 终态与跟进（10 分钟，验证 H3）

7. 你派工/审批完成之后，通常怎么确认事情落实了？
8. 有没有"做完了但不知道结果如何"的情况？当时你怎么处理的？
9. 你希望系统在完成后主动告诉你什么？

### E. 风险与告警（10 分钟，为 J2 探路）

10. 收到告警后你通常做什么？会点进去看详情吗？
11. 判断一条告警严不严重，你需要哪些信息？现在能拿到吗？
12. 处置一条告警平均要花多久？卡在哪个环节？

### F. 收尾（5 分钟）

13. 如果 EWOH 只能改进一件事，你希望是什么？
14. 有什么是你现在不得不做、但觉得完全没必要做的？

## 6. 数据分析框架

访谈结束后 48 小时内完成结构化提炼，统一填入下表：

| 字段 | 说明 |
|------|------|
| 观察编号 | OBS-n |
| 受访者角色 | dispatcher / safety_admin / workshop_lead |
| 对应假设 | H1 / H2 / H3 / H4 / 新发现 |
| 原始陈述 | 逐字记录，**不改写** |
| 观察到的行为 | 走查中的实际操作（与陈述可能不一致，需分别记录） |
| 痛点强度 | 高（主动提及+情绪）/ 中（追问后确认）/ 低（仅附和） |
| 影响频率 | 每天 / 每周 / 每月 |
| 现有变通方式 | 用户当前的 workaround（workaround 越复杂，痛点越真实） |

**优先级判定规则**：
- 强度"高" + 频率"每天" → 立即进入 P0
- 有复杂 workaround → 真实痛点，即使陈述强度不高也应重视
- 仅 1 人提及且无 workaround → 记入观察池，不单独成需求

**证伪判定**：
- 若 ≥3 名受访者都**未**主动提及"页面间切换困扰" → H1 不成立，需重新审视对象工作台的价值主张；
- 若审批场景无人抱怨"看不出是什么" → H2 不成立，OD-1 降级。

## 8. 伦理与合规

| 项 | 要求 |
|----|------|
| 知情同意 | 访谈前明确告知录音用途，取得口头+书面同意 |
| 数据脱敏 | 报告中出现的人名一律用工号或角色代称 |
| 敏感信息 | 不采集与工作无关的个人数据；涉及生产数据的内容不得外传 |
| 合规 | 遵循《个人信息保护法》：最小必要采集、明确用途、限期保存（建议 ≤6 个月） |
| 自愿参与 | 明确可随时中止，不影响绩效评估 |
