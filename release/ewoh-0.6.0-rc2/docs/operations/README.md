# 运维文档

本文件描述 EWOH 受控试点系统的日常运维、监控、告警、故障注入与应急流程。
骨架文档，部分小节为占位，将在试点运行中逐步补全。

## 每日巡检清单

每日开机前由现场运维/安全员逐项确认：

- [ ] **人员授权**：当日作业人员授权与同意记录有效，离场人员已停权。
- [ ] **设备外观**：外骨骼外观无明显损坏、线缆无破损。
- [ ] **急停**：急停按钮功能正常，按下后设备立即进入安全态。
- [ ] **电量**：设备电量满足当日作业时长需求。
- [ ] **固件**：设备固件版本与试点登记版本一致，无未授权变更。
- [ ] **传感器**：IMU/力/姿态等传感器读数在合理范围，无漂移或缺失。
- [ ] **绑定**：设备-人员-任务绑定关系正确。
- [ ] **平台时间**：平台与设备 NTP 同步，时间偏差在容忍范围。
- [ ] **磁盘**：平台与 DB 磁盘余量充足，无异常占满。
- [ ] **DB 备份**：最近一次备份成功，备份介质可读。
- [ ] **来源标识**：数据来源（real/controlled_test/simulated）标识正确，无串源。
- [ ] **应急人员**：当日应急联系人/安全员在岗，通讯畅通。

## 监控指标（四级）

### 1. 系统级
- CPU / 内存 / 磁盘 / 网络流量
- 进程存活、容器健康、端口可达
- NTP 时间偏差

### 2. 设备级
- 设备在线/离线状态、失联安全态触发次数
- 电量、固件版本、传感器健康
- 心跳间隔、丢包率

### 3. 推理级
- 推理延迟（P50/P95/P99）
- 事件检出率、误报/漏报率
- 模型版本与回滚状态
- 规则引擎触发计数

### 4. 业务级
- 在岗人员数、作业任务完成率
- 风险事件分级分布
- 数据导出次数与发起角色
- 审计日志写入量

## 告警处理

### 告警分级与响应时限

| 级别 | 定义 | 响应时限 | 示例 |
|------|------|----------|------|
| P0 | 人员安全、平台失陷、数据泄露 | 15 分钟内响应 | L3 安全事件、越权访问、RLS 失效 |
| P1 | 核心流程中断、数据完整性受损 | 2 小时内响应 | 登录不可用、审计链断裂、DB 写失败 |
| P2 | 一般功能降级或体验问题 | 下一工作日 | 页面渲染慢、单设备告警延迟 |

### 处置 SOP

1. 确认告警真实性，记录事件 ID、实体、时间与影响范围。
2. 按级别执行对应处置动作：P0 先通知安全员与值班负责人，P1 通知平台负责人，P2 记录工单。
3. 平台仅执行记录、审批、调度与数据操作，不执行设备实时安全控制。
4. 处置完成后更新事件状态并写入审计，含处置人、动作、原因与时间。
5. 每日复盘未闭环 P0/P1，形成改进项并跟踪关闭。

### 升级与交接

- 值班交接记录包含未闭环事件、告警阈值、备份状态、最近演练结果与联系人。
- P0/P1 升级路径：现场安全员 → 平台负责人 → 项目安全负责人。
- 每次告警闭环后补充复盘记录，涉及安全边界的变更需安全负责人批准。

## 故障注入演练流程

故障注入必须在隔离环境执行，并提前声明注入点与预期影响。清单见
`docs/acceptance/README.md` 的 16 类故障注入。

1. 演练前通知运维与安全负责人，确认不影响现场作业。
2. 在隔离 PostgreSQL/SQLite 环境注入故障（断连、慢查询、令牌伪造、审计写入失败等）。
3. 观测平台降级行为，验证平台不向设备下发急停/限扭/关节实时控制。
4. 恢复故障并运行 `scripts/standalone-check.sh` 或 `scripts/release-drill.sh` 回归。
5. 记录注入点、预期、实际结果、恢复时间与复盘改进项。

## 恢复演练流程

自动恢复演练：

```bash
EWOH_OPS_SOURCE_URL='postgresql://owner:...@host:5432/ewoh' \
EWOH_OPS_RESTORE_ADMIN_URL='postgresql://owner:...@host:5432/postgres' \
EWOH_OPS_RESTORE_DB='ewoh_ops_restore' \
bash scripts/standalone-ops-check.sh
```

该脚本执行：逻辑备份 → 全新恢复库建 Schema → 恢复全部 `ewoh_*` 表 →
行数比对 → 身份序列冒烟。

- 备份介质可用性：备份 JSON 可读且 `verify` 行数一致。
- 证据一致性：恢复库与源库 54 张 `ewoh_*` 表行数一致。
- 恢复后冒烟：健康检查、`ewoh_world_delta_log` 身份序列可继续写入。
- RPO/RTO 基线：试点期 RPO ≤ 最近一次备份间隔，RTO ≤ 30 分钟（本地演练实测）。

## 应急停止流程

### 触发条件

- 设备异常、人员受伤、平台失陷、安全事件升级。

### 停止步骤

1. 现场优先使用设备急停/本地安全控制，平台不参与实时安全闭环。
2. 平台侧仅记录事件、失联安全态与审计信息。
3. 确认设备失联安全态触发、平台无控制下发、数据链路停止采集。
4. 事后由安全负责人组织事件记录与上报，保留原始证据。

### 复产前确认

- 设备急停功能正常、人员授权有效、绑定关系正确。
- 平台恢复后运行健康检查、备份校验与至少一次回归测试。
- 应急事件已闭环并记录复盘结论。
