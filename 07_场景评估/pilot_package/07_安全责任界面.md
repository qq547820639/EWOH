# 07 安全责任界面

> 本文界定平台方（我方）、设备方（诺亦腾 NY-EXO-A1）、客户三方在试点中的安全责任边界。核心原则：**涉及人身安全的实时控制闭环全部在设备控制器本地执行，平台（含大模型）不进入安全闭环。**

## 1. 责任边界总表

| 域 | 平台方（我方） | 设备方 | 客户 |
|---|---|---|---|
| 关节实时控制目标 | **不承担、不实现** | 设备控制器本地执行 | 不介入 |
| 限扭/限速阈值的设置、关闭或放宽 | **不承担、不实现** | 设备控制器本地执行 | 不介入 |
| 急停与异常退出 | **不承担、不实现** | 设备本地安全机制，失联/低电/传感器异常时进入本地安全态 | 现场配合急停演练 |
| 绕过本地安全校验的调试指令 | **不承担、不实现** | 不提供此类接口 | 不介入 |
| 遥测采集/存储/展示 | 负责 | 按协议提供数据 | 提供现场条件 |
| 风险事件提示与记录 | 负责（提示与留痕，非实时保护） | 提供故障码 | 组织处置与确认 |
| 穿戴培训与使用规范 | 提供培训材料与支持 | 提供设备使用规范 | 组织人员参加 |
| 现场作业安全管理 | 不承担 | 不承担 | **客户主体责任** |

## 2. 关键约定
1. **平台与大模型均不得实现任何写入关节控制、限扭/限速、急停与异常退出、绕过本地安全校验调试指令的路径**（见《真实设备协议确认书》第 4 节安全红线）。
2. 失联、低电、传感器异常时，设备进入本地安全态并保持助力退出，该逻辑由设备控制器执行，不依赖平台在线。
3. 平台侧风险事件（如连续高负荷、长时间弯腰、设备离线）为**提示与记录**，处置动作由客户现场管理执行，不构成实时安全保护。
4. 平台允许的设备写入仅限白名单命令 IDENT_REQUEST（0x81）与 TIME_SYNC（0x82）。
